# Decision log

Newest first. Each entry: date, decision, why.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-27 | **Supabase is the planned future backend** (move the Express API to Supabase Edge Functions; Pro plan at launch, ~$25/month). | One managed platform covers the API, Postgres, auth, and storage needed for accounts and private backup; predictable cost at launch; keeps the provider abstraction intact while replacing hosting. |
| 2026-11-27 | **Community stats will be opt-in, with anonymous contributions allowed.** | Journal data is personal. Aggregated community stats must never be a default; users who opt in can contribute without an account or identity attached. |
| 2026-11-27 | **Event sources evaluated and rejected: Eventbrite, Bandsintown, Songkick, Resident Advisor, Dice.** | Eventbrite retired its public event-search API, so third parties cannot search its catalog. Bandsintown's API is built for artists and partners and requires approval, not open consumer discovery. Songkick's API is closed to new sign-ups. Resident Advisor and Dice have no public API, and scraping would violate their terms. Ticketmaster (official API) plus community submissions remain the supported sources; new sources can be added via the provider abstraction. |
| 2026-11-26 | **`Screen` owns the top safe-area inset.** | Content was rendering under the status bar when screens composed insets themselves. Centralizing the top edge in `frontend/src/components/Screen.tsx` (callers may only add non-top edges) prevents both overlap and doubled spacing; `tests/screen-top-inset.test.cjs` guards it. |
| 2026-11-26 | **expo-router only for navigation hooks.** | Mixing `@react-navigation/*` imports with Expo Router caused inconsistent behaviour and duplicate dependencies on navigation internals. An ESLint `no-restricted-imports` rule (`frontend/eslint.config.js`, enforced by `tests/navigation-imports.test.cjs`) blocks direct `@react-navigation` imports; `Link`, `router`, and hooks come from `expo-router`. |
| 2026-11-13 | **SQLite (Node's built-in `node:sqlite`) for event submissions.** | Submissions need durable, queryable storage with zero operational overhead at this scale. The built-in module avoids adding a native dependency; WAL mode handles concurrent reads; `DATABASE_PATH` keeps the file relocatable. See `backend/src/db/submissions.ts`. |
| 2026-11-13 | **Approve-first moderation for community events.** | Pending submissions are private until an administrator approves them, so spam, scams, or wrong data never reach users. Rejected submissions keep their reason for auditability. Admin access requires `ADMIN_TOKEN`. |
| 2026-11-12 | **Open-Meteo Geocoding for city search.** | Free, no API key, solid worldwide city data (GeoNames). Constraint accepted: the free tier is **non-commercial** and attribution is required (Open-Meteo.com + GeoNames under CC BY 4.0, credited in the picker). Provider specifics are isolated in `backend/src/services/geocoding.ts` so the provider can be swapped before any commercial launch. |
| 2026-11-12 | **Ticketmaster API key stays server-side.** | Expo embeds `EXPO_PUBLIC_*` variables in the shipped app, so any client-side key would leak. The backend reads `TICKETMASTER_API_KEY` at request time, never logs it, and the app only ever talks to our own API. |
